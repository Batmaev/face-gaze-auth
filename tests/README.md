# Нагрузочный тест `/islive_video`

`perf_service.py` нагружает только `POST /islive_video`. Для каждого заданного
RPS запускается отдельный профиль длительностью `--duration` секунд; `--concurrency`
ограничивает количество одновременных запросов. Скрипт локально создаёт spline
stimulus для формы запроса и обращается только к `POST /islive_video`; другие
эндпоинты не вызываются.

## Запуск по тестовым видео

Из корня репозитория активируйте окружение с `httpx` и укажите целевой API,
длительность каждого профиля, параллелизм и список RPS:

```sh
source /Users/jurinovikov/Music/projects_wb/hr_sz_proj/new_model/.venv/bin/activate
python -m pip install -r tests/requirements-perf.txt
python tests/perf_service.py \
  --url https://liveness-gpu.slay.place/api \
  --video tests/_data_perf_video \
  --duration 60 \
  --concurrency 2 \
  --rps 0.1 0.25 0.5
```

Если `--video` указывает на каталог, перед каждым запросом случайно выбирается
одно из видео `.mp4`, `.webm`, `.mov` или `.mkv` с одноимённым JSON sidecar
(выбор с возвращением, поэтому один ролик может выпасть несколько раз подряд).
Если указан конкретный файл, все запросы используют его.

Для каждого профиля терминал показывает число запросов, долю успешных ответов,
пропускную способность и статистики времени (min, mean, p50, p95, max): по всем
завершённым попыткам, успешным HTTP-ответам, ошибкам до их возникновения и
сквозному времени с ожиданием в очереди. Время ошибки не является временем
успешного ответа; эти показатели выведены отдельно. Сводный Excel-файл
`statistics.xlsx` содержит лист `Successful timings` с min/mean/p50/p95/max
успешных запросов для каждого RPS и лист `Request success` со счётчиками,
процентом успеха, пропускной способностью и распределением ошибок.

Все результаты нового запуска сохраняются в `tests/log_<run_id>/`:
JSON-сводки и построчные `requests.jsonl` — в подкаталогах профилей,
`statistics.xlsx` — в корне запуска. Директории начинаются с `log_`, поэтому
игнорируются Git. Предыдущие результаты не перезаписываются.

`--timeout`, `--connect-timeout` и `--write-timeout` задают таймауты ответа,
соединения и загрузки видео. Сервер сохраняет полученные копии под `user_id`
`perf-test` (или значением `--user-id`). Для первого прогона используйте низкий
RPS и небольшую длительность.
